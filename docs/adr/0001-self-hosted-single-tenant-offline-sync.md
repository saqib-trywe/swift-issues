# Self-hosted, single-tenant, offline-first with server-authoritative sync

This is a lightweight, self-hosted issue tracker: each server Instance serves exactly one team, with no multi-tenant/org isolation and no SaaS billing layer — ruled out to keep the system's operational weight as light as its feature set. Clients (macOS/iOS/iPadOS/CLI) work offline-first against local storage and sync changes to the server, which stays the authoritative source of truth; conflicts resolve last-write-wins per field, with the losing edit surfaced to the user rather than silently dropped. We chose this over a full CRDT-based merge because CRDT is a substantial engineering investment on its own, and v1 has no evidence yet that it's needed — full merge semantics can be reconsidered as a future effort once we've seen how often real conflicts occur in practice. v1 sync is pull-based only (foreground refresh, manual refresh, background fetch); push notifications are a known future thread, not a v1 requirement.
